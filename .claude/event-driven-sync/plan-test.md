## 0. Подготовка окружения

### 0.1. Состояние перед тестами
- [ ] Плагин собран: `npm run build` → exit 0, `main.js` обновлён.
- [ ] Лог-файл: удалить старый, если права не позволяют запись:
  ```
  rm /home/muxaujl/dev-obsidian/.obsidian/logs/sync-log.txt
  ```
- [ ] Перезагрузить плагин: Settings → Community plugins → toggle off/on.
- [ ] Открыть DevTools: `Ctrl+Shift+I` → вкладка Console.
- [ ] Открыть лог-файл в отдельном терминале:
  ```
  tail -F /home/muxaujl/dev-obsidian/.obsidian/logs/sync-log.txt
  ```
- [ ] Подготовить тестовую папку в Битрикс24 (отдельную, не основную) — все тесты идут в ней.
- [ ] В настройках плагина указать эту тестовую папку.

| Проверка | Ожидаемо |
|---|---|

| 4.8 | Ничего не менялось | Catch-up завершается без модалок и Notice |
| 4.9 | Перед запуском очистить мапу (`clear-mapping`) | Все файлы Битрикса воспринимаются как новые → создаются локально (`bitrix:create`) |

### Проверка не-блокирования
- Catch-up — fire-and-forget; UI Obsidian должен быть отзывчивым во время загрузки.
- Если catch-up зависает на запросе — пользователь может работать с vault без блокировки.

## 15. Какие сценарии НЕ покрыты текущим кодом (известные ограничения)

Эти кейсы не тестируем — они вне scope, но фиксируем как «known limitations»:

1. **Изменения из веб-UI Битрикса в реальном времени** — не прилетают (A7 отложен). Подтянутся только при следующем catch-up.
2. **Multi-client синхронизация** — если запущены два Obsidian, они не узнают друг о друге через WS. Убран `pull.application.event.add` broadcast.
3. **Прерванный push-all** — сетевые ошибки в середине не откатывают уже сделанные операции; повторный запуск дозальёт остаток (идемпотентность через path-lookup).
4. **Конфликт во время push-all/pull-all** — bulk-команды не используют conflict modal; берут локальное (push) или удалённое (pull) безусловно.
5. **Cross-file batching в push/pull** — каждая операция = отдельный HTTP-запрос. Оптимизация отложена.
6. **`local:rename` + `local:modify` в одну секунду** — dedup-ключ `local:<newPath>` приводит к тому, что modify затрёт rename. Маловероятный кейс; если воспроизведётся — менять схему dedup-ключей.
7. **Битрикс-pull-эхо на чужие client-id** — фильтр по `client` сейчас не работает надёжно; идемпотентность через mapping компенсирует.
8. **`clientSecret` в исходниках (C1)** — security-долг, не блокирует функционал.
